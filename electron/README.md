# NILEFRONT — desktop build

A thin [Electron](https://www.electronjs.org/) shell around the browser game at
[`../index.html`](../index.html). That file is untouched and stays the single source of
truth — it's still what `gh-pages` deploys to the web. This folder only wraps it in a
window and swaps its one CDN dependency (three.js) for a vendored local copy, so the
desktop build runs with no internet connection required.

## How it fits together

```
electron/
  main.js            Electron main process: opens the window, keeps it sandboxed
  preload.js         contextIsolation bridge (empty for now — see its comment)
  vendor/three.min.js  three.js r128, vendored so the app works offline (committed)
  scripts/build-app.js  copies ../index.html -> app/index.html, rewriting the
                         three.js <script> tag to point at the local vendor copy
  app/               generated by build-app.js — gitignored, never edit directly
  dist/              electron-builder output — gitignored
```

`app/` is a build artifact, not a second copy of the game to maintain: every `npm start`
or `npm run dist` regenerates it fresh from `../index.html`. If that file's three.js
`<script>` tag ever changes upstream (a version bump, say), `build-app.js` fails loudly
with what to update rather than silently shipping a build that still points at a URL
the offline app can't reach.

## Setup

```
cd electron
npm install
```

### Using pnpm instead

Works fine — nothing here is npm-specific. If `pnpm` isn't already on your PATH:

```
npm install -g pnpm
```

One extra step beyond that is required, though:
`electron`'s own postinstall script (which downloads its actual binary) ships with a
build script, and pnpm refuses to run any dependency's build script unless it's been
explicitly allowed — even with `onlyBuiltDependencies: [electron]` already set in
[`pnpm-workspace.yaml`](pnpm-workspace.yaml), a plain `pnpm install` still aborted with
`ERR_PNPM_IGNORED_BUILDS` when this was tested (pnpm v12.4.2). The reliable path is to
skip pnpm's script phase entirely and run electron's installer yourself:

```
pnpm install --ignore-scripts
pnpm run fetch:electron
```

After that, `pnpm start` / `pnpm run dist` etc. all work exactly like their `npm run`
equivalents — `fetch:electron` only needs to be re-run when `electron`'s version changes.

### If `electron .` fails with "Electron failed to install correctly"

That means `node_modules/electron/dist/` has no actual binary in it — the download step
ran but its unzip step didn't finish. Confirm with `ls node_modules/electron/dist` (a
healthy install has `Electron.app` on macOS, or `electron.exe` / `electron` on
Windows/Linux, not just a lone `LICENSES.chromium.html`). Re-run the install step
(`npm run fetch:electron` under npm's own postinstall, or `pnpm run fetch:electron`)
with nothing else running in the folder; if it keeps failing silently, extract the
already-downloaded zip yourself with the system `unzip` — `electron`'s installer caches
it under `~/Library/Caches/electron/` (macOS), `%LOCALAPPDATA%\electron\Cache`
(Windows), or `~/.cache/electron` (Linux) — into `node_modules/electron/dist/`, and
write the relative path to its executable (e.g.
`Electron.app/Contents/MacOS/Electron` on macOS) into `node_modules/electron/path.txt`.

## Run in development

```
npm start
```

Rebuilds `app/` from the current `../index.html` and launches Electron pointed at it.
DevTools: F12, or Ctrl/Cmd+Shift+I (dev builds only).

## Build installers

```
npm run dist         # this platform
npm run dist:mac      # .dmg
npm run dist:win      # NSIS installer
npm run dist:linux    # AppImage
```

Output lands in `electron/dist/`. Building for a platform other than the one you're on
may require that platform's toolchain (see
[electron-builder's docs](https://www.electron.build/multi-platform-build) — e.g.
building a Windows installer from macOS needs Wine).

No app icon is configured yet, so builds use Electron's default icon. Add one under
`build.mac.icon` / `build.win.icon` / `build.linux.icon` in `package.json` (a `.icns`,
`.ico`, and `.png` respectively) when you have artwork for it.

## Re-vendoring three.js

Only needed if `../index.html` moves to a different three.js version:

```
curl -fsSL https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js \
  -o electron/vendor/three.min.js
```

Then check its SHA-512 against the `integrity="..."` attribute on index.html's own
`<script>` tag (`shasum -a 512 electron/vendor/three.min.js | ...` re-encoded as base64,
or just diff the two files) before trusting it — the point of vendoring is to run a
copy you've verified is byte-for-byte what the web build already loads, not a new one.
